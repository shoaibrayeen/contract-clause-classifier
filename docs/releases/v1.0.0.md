# v1.0.0: first trained model, `ledgar-qwen3-0.6b-v1`

A contract clause-type classifier: paste a contract and it splits it into provisions and labels each one
(Governing Laws, Confidentiality, Indemnifications, Terminations, …) with a calibrated confidence, served
through an OpenAI-compatible API with a browser playground.

## Model: `ledgar-qwen3-0.6b-v1`

| Metric (full 10,000-provision LEDGAR test set, 78 clause types) | Value |
|---|---|
| Accuracy | **92.46%** |
| Top-3 accuracy | **97.69%** |
| Macro-F1 | 89.7% |
| Calibration error (after temperature scaling) | 2.2% (7.0% before) |

**Base model:** Qwen3-0.6B-Base (596M parameters, Apache-2.0), with a classification head; all weights fine-tuned.

**Fine-tuning:** AdamW, learning rate 2e-5, 6% warm-up, cosine decay; 3 epochs; effective batch size 32
(4 × 8 gradient accumulation); up to 512 tokens per clause; label smoothing 0.1; gradient clipping 1.0;
weight decay 0.01; best checkpoint by validation accuracy; temperature scaling.

**Compute:** a single laptop with 48 GB of memory, using its built-in GPU through PyTorch. 9 h 57 min for
5,625 training steps, about 25M tokens, about 30 GB peak memory. No cloud GPU.

**Dataset:** LEDGAR via LexGLUE, 80,000 clauses from contracts filed with the US SEC; 60k train (2016–17),
10k validation (2018), 10k test (2019). 100 labels merged into 78 clause types after a legal review of each
synonym group. The data is committed in `data/raw/ledgar/` with per-file provenance (CC BY 4.0).

**Known limitation:** LEDGAR has no labels for Limitation of Liability, Force Majeure, Non-Compete,
Non-Solicitation, Audit Rights, Exclusivity, Warranty Disclaimer or Liquidated Damages; the model maps such
clauses to the nearest type it knows, usually with lower confidence.

The model weights are not attached to this release (1.2 GB); train them with `make all` (about 10 hours on
a 48 GB laptop), which reproduces this version from the committed data and config.

## Highlights

- **Model versions:** every run creates `<run_name>-v<N>`; nothing is ever overwritten; the API serves all
  versions and defaults to the latest.
- **Playground** at `/playground`; **OpenAI-compatible API** (`/v1/chat/completions`, `/v1/models`,
  `/v1/dataset`, `/v1/labels`, `/health`); **Docker** image.
- **Training telemetry** for every step, replayable as GIFs: training charts, the terminal dashboard epoch by
  epoch, and a recorded playground session (see `demo/`).
- **Rules for every AI assistant** (Claude, Cursor, Codex, Copilot, Gemini, Windsurf, Cline, Roo, Continue,
  Amazon Q, Junie, Zed, Aider) generated from `AGENTS.md`.

## Breaking changes since 0.1.0

- Models predict 78 clause types instead of 100 (`data.label_groups: null` restores the original labels).
- Default training is full fine-tuning; LoRA is `full_finetune: false`.
- Runs are named `ledgar-qwen3-0.6b-v<N>` (was `ledgar-qwen3-0.6b-lora`).
- API settings: `RUNS_DIR` replaces `MODEL_DIR`; `/health` fields changed.
